# v0.2.5：限制一条经验的传播范围

实验基于 v0.2.4。四名研究员仍各自完成整题，RSI 继续观察原始轨迹、提出非阻塞建议。本版只测试经验传播范围，不启用重启或新的建议决策记录。

启动时选择 `passk_guided_v025`，对应三个模块：`leader_guidance`、`leader_guidance_v024`、`sharing_quota`。默认选项仍保留为 v0.2.4；旧版本的提示词及冻结记录不变。

## 具体变化

一条来自 A 的经验在整个研究中最多分享给一名新研究员 B。给 B 的补充和纠正仍然允许，也可以把反馈传回 A；不能再通过 B 的转述把同一经验分享给 C。

RSI 使用原有 `advise_researcher` 工具，在 `experience` 中填写名称、来源、结论、适用条件和已有经验来源，`references` 引用原始记录。系统保存经验与接收者，超过人数时拒绝发送消息。仅依据接收者自己的记录或独立调研给建议时，`experience` 为 null；从同伴轨迹总结的建议仍须登记来源。

状态查询不再自动给研究员附上所有同伴的最新报告。这是本版明确包含的调整：否则查询预算就会形成隐含广播，单独限制建议工具不足以控制传播。研究员仍可按需读取同一 run 的记录、轨迹和候选；不增加跨 run 权限。

经验记录保存在研究状态中，每次发送也有独立的材料记录。leader 的恢复状态使用当前模块的完整状态接口，包含经验记录，不只在主动调用 `get_state` 时才能看到。原始轨迹和历史候选始终保留。

新增提示只作为 Markdown 片段接到 v0.2.4：`agents/rsi/sharing_quota.md` 和 `agents/research/sharing_quota.md`，由统一读取器加载。它们不包含题目算法或 benchmark 特定建议。

## 本实验能说明什么

系统能严格限制已登记经验的新增接收者，不能仅凭字符串证明两个不同名称是否在说同一件事。因此分析需要检查重复登记、未标来源和转述关系。主动读取同伴资料也是另一条信息路径，单独统计，不能把本版描述成完全的信息隔离。

v0.2.4 和正在进行的纯 pass@4 对照均出现了独立选择相同初始路线的现象。本版不能保证解决这种趋同；要观察的是后续共享是否保留不同尝试，以及有限的帮助是否仍能纠正实际困难。

每批结束后比较最终正确性、有效成绩、候选撤回、路线变化、消息是否采用及 leader 开销。若主动读取成为主要传播渠道，再单开消融，不在当前实验中途改规则。

## 本批一并修正的发送反馈

前一批有两条建议在接收者个人预算结束后才发送，工具仍返回 queued，但消息没有被读取。
建议工具现在会明确拒绝已经停止的接收者。这项小修复单独记录，不延长预算，
也不改变预算内的正常消息；原始实验结果保留，不把这两次晚发当作整轮工程失效。
