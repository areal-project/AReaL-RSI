# 检查数据搬运

从公开输入到输出逐步追踪 shape、stride、dtype 和数据的产生/消费位置。
记录重复加载、布局转换、临时张量和可复用数据，估计流量时注明假设与缓存影响。
通过可用 profiler 或分段计时确定值得优化的热点，不能仅由代码外观判断瓶颈。

每次选择一个假设，例如消除一次中间写回、改变分块或直接写出目标布局。
保留原候选，实现后验证边界、非连续访问和同步是否正确，再做完整任务的正式评测。
每次调用都需要的转换与预处理必须计入，不假设数据可跨调用免费复用。

记录改动、条件、诊断观察和正式成绩的作业引用。若流量减少而总时间未改善，
检查计算、同步、资源占用或工作规模，按证据调整方向。不要把估算带宽当成硬件实测值。
