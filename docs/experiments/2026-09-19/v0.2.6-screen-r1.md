## 新机制实际改变了什么

三题发送建议 10/14/27 次，显式确认 10/14/26 次；读取原始轨迹 72/41/87 次。leader 输出约 39.1k/54.3k/40.0k token，researcher 合计约 151.3k/158.1k/131.1k。更少建议不等于很少协调开销。

建议均包含问题、依据、局部修复或研究假设、待验证问题和跟进。本版未叠加共享人数限制或重启。原始轨迹中能看到实际纠正：

- Astra 对 grid 的建议到达时，研究员已经测试并得到负结果；leader 跟进时承认它不能算建议带来的新实验。
- Sol 的 3D grid 假设失败后被修正，cat/interleave 的正式变慢结果也传给另一位研究员，避免继续重复。
- Astra 曾把加速归因为静态展开，随后看到动态循环配 stage 1 也快，主动撤回这一归因。

这些是协作质量的进步，但记录一个合理问题不能保证后续搜索有效，也不能替代独立分支真正完成困难的子问题。

## Astra L2：保留不同路线，也及时处理反例

探索包含 1D/2D Winograd、显式 TF32、BF16 分解与布局方案。BF16 三项曾通过正式随机校验并达到约 4.81×，但后来在缩放/相消证据下撤回。F4 Winograd 也有正式通过，随后 seed 123、100 倍随机输入出现超差；另一人 seed 1234 通过不能推翻这个具体反例。leader 传递了具体复现条件，接收者撤回相同公式，而非笼统宣布整条 Winograd 路线失败。

R3 最终靠显式 TF32 位处理及寄存器配置达到 0.313 ms。其他人也参考了这一实现，但仍各自做性能和数值检查。本版保留的独立尝试和反证共享比一刀切限额更自然；不过相对纯 pass@4 的约 5% 最终优势不足以单次证明效果。

## Sol L2：有实质共享收益，但过早判断瓶颈且缺少值域检查

起初有 CUDA 直接卷积与 Triton implicit GEMM 等路线，随后 BF16 三项、无 N mask 和 tile 128 的组合逐步传播。leader 曾几次沿用“接近带宽下限”的说法，但没有测得足以支撑这一判断的下界，后来仍连续突破。R4 在 tail-K8 两次语法失败后转向同伴方案；R2 后来完成 tail-K8 实测变慢，这个后来的负结果不能倒推早先放弃时已经有充分依据。

R3 后期切到 FP16 三项，row grid 达到约 0.338 ms，再用宽度 128 的底层存储、126 的合法输出视图达到 0.306 ms。这里有结构性布局收益，不只是继续微调 tile。最后三分钟才分享 row-grid，其他人没有全部恢复到同一性能前沿。四人最后分数仍相差明显。

本题研究员 **没有提交任何 diagnose 作业**，主要依赖正式五次随机检查；轨迹中明确出现“当前输入/参数初始化范围安全”等判断。操作侧补充检查发现，本版及 v0.2.4 的 Sol 最终实现对 `x=1e5、weight=1e-6、bias=0` 的有限 FP32 输入/参数会产生 NaN，而 reference 为有限约 3.6。两版的无缩放 FP16 中间值溢出。

正式随机协议成绩原样保留：该反例超出题目公开的 `[0,1)` 输入采样范围，不是本轮正式评分失败，也不能据此断言故意作弊。但它说明不能把这两个高分当作完整 FP32 值域上无条件成立的语义优化。四批全部八份 L2 最终实现接受同一检查，另外六份通过；相消检查八份均通过。补充检查隔离在操作侧，不反馈给 agents、不改变选择或分数。未来若扩大任务的值域要求，应在任务适配器明确定义并补同条件控制，不能在本轮中途暗改协议。

## L3：局部事实有价值，完整正确性仍被留到最后

四人初版在接收建议前，就独立选择相近的 NHWC / tf32x3 / BN 路线，不能把起始相似都归因于共享。R1 在个人有效时间约 15.56 分钟已验证 13 个代表卷积逐位一致，所以“完全没检查卷积、只盯 BN”的早期猜测不成立。真正的困难是不同 BN 形状下的统计顺序、线程映射与舍入组合。

1. 中段 R4 构造相消输入，发现普通两遍求和无法解释 reference 的均值。leader 在约第 27 分钟把反例传给另外三人，并指出它还不足以唯一证明 Welford。这次广播打开了假设，而非简单要求所有人照搬领先者。
2. R1 于 **42.22 分钟**正式报告首层 mean/inv/output 精确匹配。leader 约两分钟后核查并共享缩放与 epsilon 的 FMA 细节。但首层成立并不意味着其他尺寸成立，三人随后仍未完成整题。
3. R1 约 48.81 分钟把模板参数 128 误认为实际线程数，尝试 BS128 失败，50.64 分钟自行报告映射不吻合。leader 也查看 profiler 的实际 512 线程配置，指出应区分 **4×128 的映射**与“总共 128 线程”。
4. R1 在 **55.15 分钟**首次整题正式正确，耗时 19.8 ms、0.4864×；58.33 分钟将后段卷积换更快实现，达到 12.7 ms、0.7583×。其他三人全程没有正式正确候选。
5. 4×128 的完整局部证据于约 57.7 分钟共享。R4 那条建议在 19:05:02Z 发出，19:06:09Z 的 `run_job` 返回里确实带到了模型；之后约一分钟预算到期，没有显式确认和可观察到的采用。不能写成消息丢失，也不能写成已采纳。

对照 pass@4 的赢家 R3 在约第 43 分钟已写出相似 4×128 在线统计核心，45.18 分钟报告首层/后续层的精确结果，**45.78 分钟**首次整题正确，剩约 14 分钟做性能改进，最终 8.90 ms。本版从首层精确到整题正确又用了约 13 分钟，只剩约 5 分钟，并且最快实现的独立种子仍失败。

诊断量 150 对控制 165，不是几乎没有实验；没有 API 故障。leader 的原始读取和问题细化确实帮助澄清局部机制，但共享没有把四人变成四条完整正确的后续性能搜索。需要更早覆盖形状差异、让不同假设获得完整验证机会；不能只把同一条局部好消息反复传达。单轮也不能证明某一次建议“造成”了额外 9 分钟。

## 工程检查与决定

所有 430 个冻结源码文件在研究期间保持不变，原生执行退出正常，无新增关键执行故障。少量读取不存在的 stdout、自己使用错误导入路径和 checkout 未保存保护均有记录；这些是工具使用失败，不足以解释全局差距。工具往返通常数秒、尾部十余秒，包含实际工作及协议，不能全部认定为纯框架开销。

本版虽然提高了建议可审查性，但没有达到预定晋级条件：两个 L2 相对 base 仅约 10.5% 和 8.5%，且 L3 最终正确性失败；Sol 的高分还有值域限制。因此暂不消耗三题 Astra 晋级复测预算。

下一批独立测试 v0.2.7 的受控回滚和新会话，保留 v0.2.4 为共同 base，不叠加 quota 或本版决策表。停滞判断不能以暂时没有正确分数代替：控制的赢家在 45.78 分钟才通过，中途也有明确的诊断进展。记录真实 reset 理由、原路线、新上下文和剩余预算；不触发 reset 的条件只算暴露到该策略，不能当作 reset 的效果证据。
