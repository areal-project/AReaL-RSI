# KernelBench 独立研究规则

阅读 tasks/<题号>/reference.py 和 baseline.json，编写自包含 model_new.py，定义构造函数与 forward 语义一致的 ModelNew。baseline.json 是本次研究开始前校准的固定参考耗时，所有研究员共用。

- 使用自定义 Triton/CUDA 实现计算。允许 torch 分配、视图和复制，禁止 torch 算术、库计算回退或 torch.compile 代替自定义实现。
- 每次 forward 都根据当前输入和参数计算。禁止缓存或预先计算答案、猜测随机输入、修改 RNG 或计时。允许固定形状优化，以及严格保持原始语义的化简。
- 固定使用 strict-fp32-v1：FP32 reference，reference TF32 关闭，5 次随机正确性检查、100 次 CUDA event 计时。不能修改评分器、精度或后端全局开关。
- 探索加速比 speedup = 固定参考耗时 / 本次候选耗时，以此比较方案。measured_ref_ms 和 measured_speedup 保留当次原始测量供检查，不是探索成绩。
- 诊断入口会关闭参考计算的 TF32，并打印精度设置。保持这些设置；诊断中的通过不能代替正式评测。每次选择一个配置进行实验，不在单次作业内扫描多组配置。
- 探索种子为 42，最终独立复测由系统使用 seed 137。诊断不能使用专供最终复测的种子，最终反馈不能再用于修改候选。
- GPU 仅通过 evaluate_task / diagnose_task 作业使用；提交次数不限。用 run_job(wait=true) 等待，慢、断线或重试时先检查原作业，避免重复提交。本地主控不做 GPU 计算，CPU 内存不超过 2 GiB。
- 开始时主动联网调研通用方法、论文和文档，后续按需要继续调研。不得搜索、获取或照搬本题答案，不读取其他研究或 baseline 的候选源码。
- 只操作自己的工作区。不使用 SSH、队列直接接口或凭据，不读取评分器、SDK 内部、父目录、其他会话或旧研究。
- 独立完成整题，自行选择和调整方法。可以向 RSI 报告进展，但不等待技术指导，不与其他研究员交换信息。提交一个版本或完成报告后仍继续探索，直到系统停止。

只有正式验证的正确结果计分。发现具体错误或违规时记录原因并撤回受影响的候选；一般失败不会抹掉早先的正确版本。探索结束后，系统只对正式成绩最好的有效产物做一次独立复测；最终加速比沿用当次参考耗时/候选耗时，与已有 baseline 的最终评分一致。无需研究员重复提交。
