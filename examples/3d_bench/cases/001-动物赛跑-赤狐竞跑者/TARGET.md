# MODEL-001｜赤狐竞跑者

## 独立任务

为《动物赛跑》创建“赤狐竞跑者”的程序化 Three.js 模型。圆润赤狐，橙红毛、白胸和蓬松白尾尖；四足竞跑姿态。

本任务可脱离其他任务独立执行。以下约束已经包含完成本题所需的外观、尺寸和运行时信息；不需要访问其他项目文件。

## 建模范围

- 必须完整表达“赤狐竞跑者”的主体、关键识别部件和必要的结构层次。
- 对可运动、可换色、可显隐或可挂接的部分拆成独立命名节点。
- 可以加入少量与该模型绑定的表现组件，但不得把其他独立模型或整套场景塞入本文件。
- 不复制受版权保护角色的精确外观；涉及致敬对象时只保留抽象玩法角色与通用类型特征。

## 建模事实

以下内容是本任务的直接建模依据。应保留其中与身份、外形、尺寸、枢轴、朝向、材质、挂点、碰撞代理、动画和绑定表现有关的约束；玩法数值只用于理解模型结构，不要求在 `model.js` 中实现玩法系统。

> ## 2.1 边界与统一记录模板
> 
> - 本模块只描述「可被生成/渲染/碰撞/交互的对象」的规格与身份。动画与 VFX 不另立模块：角色动作写在对应动物素材下，环境/能力特效写在所属素材的 `bound_presentation` 下。
> - 碰撞代理和碰撞层属于本模型模块；空间边界和触发后的玩法反应由宿主系统处理。
> - 统一字段顺序（每条素材固定，不得以尺寸表开头）：
>   `名称/ID → what_it_is → species_or_item_type → game_role → appearance → dimensions_and_pivot → runtime_contract → bound_presentation`。
> - 所有模型：单模型 <80k 三角形、贴图 ≤1024²、低多边形玩具感（圆润、大面、饱和色、无写实 PBR 细节）；枢轴=底面中心，正面轴=+Z，单位=米。
> - 持久字段：除「胡萝卜库存/解锁/属性」外无对象级持久字段（比赛内对象均为瞬态，刷新即弃）。

> ### AST-FOX-01 赤狐（Red Fox）
> - **what_it_is**：一只橙红色、白胸白尾尖的卡通赤狐，体型最均衡的四足动物，玩家默认操控、代表「稳定均衡」的选手。
> - **species_or_item_type**：动物/赤狐；竞跑选手。
> - **game_role**：玩家默认载具+签名能力「极速疾跑」载体；AI 候选。
> - **appearance**：橙红皮毛#E8703A、胸腹与尾尖#F5F1E6、耳尖#3A2A22；大三角耳、蓬松大尾；圆润大眼、小黑鼻；整体圆润无尖角（玩具感）。高饱和暖色保证在草地上可读。
> - **dimensions_and_pivot**：包围 0.92(宽)×0.7(高)×1.5(长)；枢轴=髋部底面中心；正面轴=+Z（鼻尖方向）。四足站立，跑动时躯干前后俯仰 ±6°。
> - **runtime_contract**：
>   - Collider=胶囊（半径 0.42、高 0.72）+ 4 个轮采样点（前后轮距 0.9 m，左/右偏 0.32 m）用于表面判定；碰撞层 `layer=racer`。
>   - 可交互层：racer↔racer 软推挤、racer↔rail 硬边界，以及与 pad、oil、checkpoint 的触发交互。
>   - 状态：`COUNTDOWN / DRIVE / ABILITY_ACTIVE / SLIP / SHIELD / CHARGE / FINISHED / RECOVERING`。
>   - 生命周期：PREP 时按发车位 spawn → 比赛全程 → FINISHED 后停跑播放庆祝 → 离开场景 destroy（瞬态，不持久化位置）。
>   - 持久字段：无（能力/属性读 0.6 表，不存实体）。
> - **bound_presentation**：
>   - 骨骼/动画：`idle`(蹲坐待机) / `countdown`(蹲-伸) / `run`(四足跑循环，腿摆与速度绑定 0—13 m/s) / `steerL`/`steerR`(躯干偏航 ±14°) / `dash`(疾跑前倾+尾平) / `slip`(四脚打滑抖动) / `charge`(鹿角不适用) / `finish`(跃起摇尾)。
>   - 能力 VFX（绑定本动物，播放点=能力释放事件）：`VFX-FOX-DASH`=贴身橙色速度线（贴地 不放大全屏，R-03）+ 尾焰拖尾；生命周期=能力时长 4.0 s；低画质档=仅速度线关拖尾。
>   - 音频标签绑定：奔跑、打滑、能力释放。

## 交付要求

- 只交付一个文件：`model.js`；不得依赖 GLB、GLTF、FBX、OBJ、图片或远程资源。
- 使用 Three.js ES Module。`model.js` 必须导出 `createModel(THREE, options = {})`，返回一个独立 `THREE.Group`。
- Group 根节点名称必须稳定；所有可动部件使用有意义的英文节点名，并通过 `group.userData.parts` 暴露。
- 如模型含动画，额外导出 `updateModel(group, deltaTime, state = {})`；没有动画也要提供空实现。
- 文件不得创建 renderer、scene、camera、灯光、游戏循环、DOM 或全局事件监听，不得修改传入场景。
- 几何体必须在代码中程序化生成，默认枢轴位于底面中心，正面朝 +Z，单位为米。

## 三渲二美术规范

- 风格为动画感三渲二：清晰剪影、简化大色块、圆润或有控制的低多边形造型。
- 使用 2–4 档明暗色阶；优先 `MeshToonMaterial`，可辅以少量 emissive、透明面片或顶点色。
- 为主要轮廓增加可选描边：倒壳描边或兼容后处理的 outline 标记；描边不得导致明显穿帮。
- 不使用照片纹理、写实污渍、复杂 PBR 噪声或微表面细节；颜色和形状在中远景仍须可读。
- 默认材质支持外部主光；模型自身不得添加灯光。透明材质需控制排序和深度写入。

## 代码与验收契约

- `createModel` 可重复调用且实例互不共享可变状态。
- `options` 至少支持 `scale`、`palette`、`outline`、`quality`。
- `group.userData.bounds` 提供 `{ width, height, depth }`；`group.userData.modelId` 与任务 ID 一致。
- 所有 Mesh 开启合理的 `castShadow/receiveShadow`；装饰面片按需要关闭投影。
- 提供 `disposeModel(group)`，释放本实例创建的 geometry、material 和 texture。
- 在空 Three.js 场景中调用后必须立即可见；控制台无错误、无 NaN、无网络请求。
- 最终只验收本任务目标模型，不实现玩法判定、AI、HUD、音频和完整场景。
