# RSI 最小训练闭环交接

## 目标与代码位置

目标是实现一个 ToRL 数学 TIR Agent 的最小 RSI 闭环：冻结任务和 `M0/H0` → 根据公开失败反馈提出并选择 `H1` → 固定 `H1`，由 AReaL 2.0 recipe 在 Slurm 上做 GRPO 得到 `M1` → `M0H0/M0H1/M1H0/M1H1` 配对评测 → 记录发布或拒绝决定。数据合成与 SFT 暂不在首个运行路径中。不要把 CPU 模拟测试当成真实训练或能力提升。

- RSI：[GitHub `areal-project/AReaL-RSI` 的 `dev/0928`](https://github.com/areal-project/AReaL-RSI/tree/dev/0928)。这是从空历史建立的分支，旧 RSI 分支仅供参考。
- AReaL：[GitHub `daihaowz/AReaL` 的 `dev/0928`](https://github.com/daihaowz/AReaL/tree/dev/0928)，当前依赖提交 `ae6f50fd01f129856729b8daddabea1db272f3ce`。包含 TIR prompt/严格奖励与安全计算器、rollout `source_task_id`、SGLang worker 版本校验；多余的 Ray 补丁已回退。
- 通用进程接线在 `src/areal_rsi/scripts/`；ToRL/TIR 题集、Harness、reward、workflow、训练/评测 recipe 和运行入口在 `examples/areal_rsi_tir/`。AReaL 的 `examples.tir` 与本项目的 `areal_rsi_tir` 是两个不同的包。
- 操作步骤和配置示例见 [`examples/areal_rsi_tir/README.md`](../examples/areal_rsi_tir/README.md)；阶段证据见 [`implementation-status.md`](implementation-status.md)。

## 已验证的事实

- `make check`：Ruff、Mypy、17 个 CPU 测试通过；无 AReaL checkout 的标准环境跳过 2 个可选跨仓库测试。
- 在 AReaL Python 环境设置 `AREAL_CHECKOUT` 后，2 个跨仓库 CPU 测试通过：假推理引擎产生完整评测报告与 token/mask 轨迹；假训练器产生带任务 ID 的 rollout 和检查点收据。
- `uv build` 可生成同时包含 `areal_rsi` 与 `areal_rsi_tir` 的 wheel；示例 CLI 是 `areal-rsi-tir`。
- 本机已有 ToRL parquet 快照完成转换与冻结：原始 train/test 为 28,740/374 行，去重后 28,738/194 题。该快照和生成文件位于本机临时目录，另一台机器需重新取得来源文件并冻结。
- AReaL 训练/评测 recipe 的 `--validate-only` 与 CPU `FrozenTIRWorkflow` 构造通过；使用的是极小占位模型/tokenizer，不是目标模型推理。

## 接手后的顺序

1. 从上述两个 GitHub 分支获取代码；先核对两个 HEAD，安装相匹配的 RSI wheel 与 AReaL checkout。运行 `make check`，在 AReaL 环境运行 `AREAL_CHECKOUT=/path/to/AReaL pytest -q tests/test_areal_recipe_integration.py`。
2. 核实 ToRL 文件的来源/许可证、目标 Slurm 分区与每节点 GPU 数、共享路径、模型快照、SGLang 版本。冻结题集、`H0` 和配置；用真实 Qwen2.5-Math-1.5B 资产执行 recipe 的 `--validate-only`。
3. 在目标 Slurm worker 完成一次真实 `M0H0` TIR rollout，确认计算器工具、reward、模型/Harness/源码摘要及逐题轨迹。复测 A/A 波动。没有这一证据，不启动完整训练。
4. 接通研究员模型接口，用真实 `harness_evolve` 失败反馈提出 `H1`，在 `harness_select` 一次选版；验证同题采样有足够的混合奖励。
5. 做一个真实 GRPO step 烟测，核对 Slurm job ID、完整可重载检查点、覆盖 `model_train` 的 rollout dump。随后按预登记预算完成训练和四组 dev/sealed 评测，保留失败或无增益的决定。

目前没有目标 GPU、真实 Qwen 推理、训练 step 或封存集结果；P1–P4 的集群验收仍未完成。遇到外部作业结果缺失时，先看 `runs/<run-id>/jobs/<stage>.log` 和 Slurm 中的原 job ID，不要用同一训练身份盲目重提。
