# v0.2.7：回滚并重新探索

本版在 v0.2.4 的持续观察与非阻塞指导上，增加可选 `researcher_restart` 模块。
未叠加 v0.2.5 的共享限额或 v0.2.6 的决策记录。前两版未达到晋级条件，本轮固定从 v0.2.4 独立出发。

RSI 先检查停滞的原始证据，不能只凭低分判断。约 15 分钟有效时间没有推进、且完成了至少三次有结果的尝试，是审视时机，不是自动清空条件。
有新的正确性证据、明确排除一个假设、或正在完成有希望的改写时，仍可能是在前进。

需要换个起点时，RSI 先用 `advise_researcher` 给出简短说明，再用 `restart_researcher` 引用这条消息和该研究员自己的历史候选或公开起点。
系统保留当前最好研究员；每个槽位最多重启一次，全研究最多重启一半，逐个执行。申请与旧作业收尾后都检查至少还有三分之一的个人有效预算。

切换时先取消旧回合，关闭该会话的原生进程和工具连接，收齐在途冻结作业，再归档当前工作区、恢复起点并开启新会话。
旧候选、最好结果和原始轨迹继续保留；新会话只接收原任务、恢复起点与 RSI 本次说明，不灌回旧 compact 或积压消息。
整理和重启成本计入原预算，不新增研究员、不增加一小时。

`get_state` 提供切换状态、当前和历史 `session_id`。`read_researcher_trace` 可显式读取同一 run 中指定研究员的历史会话；空字符串读取当前会话。
原始证据访问边界不变。新模块不能通过重启读取其他 run，也不能直接用同伴整个候选作为重启起点。

固定角色文字位于 `agents/rsi/researcher_restart.md` 与 `agents/research/restart_task.md`。任务适配器只说明本版允许在原槽位、原预算内重新探索，评测协议不变。

验证覆盖预算继承、归档与恢复、旧作业排空、旧消息不回灌、历史会话权限，以及原生会话关闭不会关闭其他研究员。
没有触发重启的研究不能证明本机制有效或无效；实验报告须单列实际重启次数、原因、剩余预算与后续轨迹。
