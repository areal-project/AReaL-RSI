后期延迟继续定位：在已结束 L2P71 的元数据副本上，481 个作业的空闲 polling 中位数约 35 ms；研究员/leader 的恢复状态重建分别约 58/68 ms。AReaL Runtime 只在 delivery 时消费这份状态，engine 却在每次工具完成后同步重建。已在隔离代码副本中实现跳过这项无用工作的修复，原生会话恢复、pass@k 启动、身份保留和旧 Responses compact 四项检查通过；当前研究结束后已部署 r4，正式源码与通过验证的副本逐字节一致。旧 Responses 的回合内状态刷新保留。这项优化的实际延迟收益仍需在下一批三题并发中观察，不先宣称后期延迟已全部解决。

诊断真实 GPU 验证已补齐：`inline-jit-audit/result.json` 记录配置中的 L20X 上直接定义 JIT kernel、源码定位、future import、脚本参数、严格 FP32 和实际输出均通过；此前本地解释器缺少 Triton 的回执不能作为这项成功证据。

实际三题并发验证：Luna 前两波均已跑满一小时，普通报告和指导的后十五分钟中位耗时维持在约 0.4–1.0 秒，没有重现原先持续 5–10 秒的后期阻塞。部分停止边界调用仍较慢，不能据此声称所有延迟消失；原始分段记录见本轮各阶段的 tool-latency.json。
