# 每名研究员的有效时间

pass@k 及其附加模块支持 `brief.limits.max_effective_seconds`。这次 v0.2 使用
3600 秒，并将 `max_wall_seconds` 设为 null。每名研究员独立计时、到时停止；
RSI 随最后一名研究员结束，随后统一冻结选优并独立复测。

当前有效时间仅支持 Codex。standard 尚未提供 API 故障时间事件，请使用
`max_wall_seconds`；启动时会拒绝不支持的组合，避免用不同口径比较。

口径 `baseline-active-v1` 对齐 KernelBench baseline 的 `budget_time.account`：

```
有效时间 = 研究员工作时段 − union(API 故障等待, GPU 排队)
```

- 正常 API 请求、模型推理、联网调研、编译、GPU 执行均计时。
- API 故障同时观察 Codex 错误通知和原生 HTTP 状态。内部 HTTP 请求失败或收到
  408/429/5xx 时，记录从本次请求开始到重试收到成功响应头的区间；上层流式错误
  仍从错误通知计到新的输出或新增 token 用量。两者取并集，不重复扣时。
- Runtime 从原生进程 stderr 即时提取时间与状态，不保存 URL、请求正文、响应头或凭据。
  SQLite 日志存在批量落盘延迟，故不用于实时计时。没有可确认故障的普通请求延迟仍计时。
- GPU 排队使用适配器回执中的 `created_at` 到 `started_at`；未运行即结束的作业使用
  `finished_at`。本地作业并发队列也扣除。重叠等待只扣一次，且只影响该作业所属研究员。
- 如 baseline 一样，即使研究员在自己的 GPU 排队期间做了其他工作，该排队区间仍扣除。
- 两次工作台进程运行之间的维护间隔不计时；异常退出恢复以最后一次持久心跳为界。
  暂停期间也不计时，恢复后继续原预算。
  正常轮次之间的监督和消息处理仍在工作时段内，不另行免计。

若本地执行进程已结束，而最后一份远端回执仍显示排队，排队扣时最多计算到本地结束。
核心不会额外连接某个 GPU 服务查询状态；适配器提供更新的起止回执时使用其中的实际时间。

时间区间保存在 `coordination/state.json` 的 `effective_time` 中；工作台研究详情展示
每名研究员的有效时间、GPU 排队和 API 故障等待。通常每秒检查预算；远端回执每五秒
刷新，所以停止时间有秒级采样误差，保留实际值，不把超出部分改写为恰好一小时。

有效时间模式的 agent 状态不再混入从整组启动时算起的 `elapsed_seconds`。
没有整组墙钟上限时，也不提供墙钟倒计时和截止时间；若明确设置了这个额外上限，仍显示其剩余时间。
RSI 能查看所有人的预算，研究员只看到自己的。
工作台仍单独展示包含启动准备和等待的“总历时”；研究节点直接展示有效时间和个人剩余时间，
详情中的实际历时从该研究员真正开始执行时计算。

每名研究员的实际停止时刻另行冻结。最终选优同时检查整组和个人截止时间，
不接受个人停止后才完成或无法追溯归属的 GPU 成绩。旧墙钟实验的配置和记录不变。

Runtime 的 `0.4.0.dev1+rsi2` 增加 Codex API 可用性事件与内部 HTTP 重试区间，补丁和可重建脚本在
`vendor/`，原始 wheel 保留。原生模型循环、重试策略、工具、历史和 compact 均未改变。
