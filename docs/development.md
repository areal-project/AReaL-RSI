# 从 Web 发起研发

工作台从数据目录的 `development-profiles/*.json` 读取操作员登记的执行配置。
这些配置、环境凭据、项目路径和验收脚本属于部署数据，不放入 RSI 源码。
浏览器不展示执行配置名称、仓库目录、代码基线、尝试数量或单独的验收要求。

用户在“新建研究”中只需描述“你想完成什么”，可以直接写功能、约束与完成标准。
模型与运行设置默认收起；必要时可展开修改。已配置工作区时，系统自动准备，检查通过后启动。
部署可通过 `ResearchConfig.metadata.development_profile_id` 指定当前工作区的执行配置；
只有一个配置时可自动采用。有多个配置但未指定默认值时，不擅自挑选项目，继续通过对话明确任务。

Web 创建使用 `use_workspace: true`，仓库、基线与并行数由服务端解析。
用户的完整目标原文同时作为准备请求的需求输入，不再与另一段默认验收文案拼接。
文字要求会指导研究员，不等于可信验证器已经覆盖；环境准备不得静默忽略不支持的要求。
原有完整 `development` 请求保留给明确配置执行条件的 API 调用方。

总时限默认留空（不限），页面不会从执行环境预设自动填入时限。只有用户明确
填写后才启用墙钟截止；API 省略 `wall_seconds` 或传 `null` 也表示不限。
未设置时限或可信验收目标时，可由用户手动停止。已有任务的明确时限保持不变。
预检不会启动研究 Agent。检查通过后点击“开始研究”，才开始计算研究预算。

## 配置与预检约定

配置采用 `DevelopmentProfile` 契约：`profile_id`、`title`、`description`、
`defaults`、`prepare_command` 和可选的 `timeout_seconds`。
`defaults` 使用 `DevelopmentSetup` 契约，包含仓库、基线、验收要求、并行数和时限。
`prepare_command` 是操作员提供的固定 argv，其中 `{request}`、`{output}`
必须各占一个完整参数，不通过 shell 拼接用户输入。

预检进程收到系统写入的 JSON 请求：`run_id`、`setup` 和当前 `config`。
进程在指定输出目录写入：

- `checks.json`：`PreparationCheck` 列表，逐项包含名称、状态和说明。以原子替换方式更新。
- `config.json`：检查通过后生成的完整 `ResearchConfig`，登记固定执行命令、候选归档与可信验证器。

预检必须基于用户选择准备工作区和执行环境，不得更改模型、认证、协作方式、
目标、并行数或时限。执行器负责检查与拒绝越界的仓库、基线、资源和验收要求。
只有进程成功退出、所有检查通过、配置身份未变化，系统才允许开始研究。
模型设置变化后必须重新预检；执行配置在正式启动后锁定。

预检由现有持久作业管理器执行，刷新页面或重启工作台不会重复提交仍在运行的作业。
失败后可在页面重新预检。作业通过后，系统登记其准备好的配置及任务说明。

## 隔离与结果

命令模板可使用系统绑定的 `{run_id}`、`{agent_id}`、`{workspace}`、`{output}`，
调用者不能传入这些参数伪造其他尝试的身份。执行器必须根据受信绑定限制远端工作区，
并独立处理远端作业恢复和取消；仅把工作目录设为不同路径不构成访问隔离。

模型自述和普通命令退出成功不构成正式验收结果。需要自动达标时，应配置现有
可信验证器，冻结协议身份，并把结果绑定到不可变候选内容。
没有可信验证器的限时研究只收集候选，不能标为已经通过自动验收。

## 页面操作与交付

预检运行时可以取消，状态会先进入取消中，确认作业结束后才开放重试。
准备好的配置若被修改，启动按钮重新关闭，必须重新预检。预检结果接管与
启动控制使用同一个运行锁，另一个控制器持有运行时只读取状态，不覆盖其转换。

研发启动后自动收起环境检查和配置面板。固定条件研发不显示无效的对话入口，
研究员详情展示最新公开执行说明；作业的 `progress.json` 可持续上报实际远端队列状态。

页面可以下载候选源码，以及已结束验证作业的公开验收报告。报告导出只包含
该作业配置的 `public_output_subdir`，不包含私有验证输入或原始私有日志；拒绝符号链接。
部署适配器负责把适合用户阅读的报告放入这个公开目录。

## 运行中的人工指导（pass@k）

在研究员详情中点击“指导这个 Agent”，消息只进入这一路的收件箱和恢复上下文。
页面区分“已保存 · 待送达”“已送达 · 等待回复”和“Agent 已回复”；回复不是验收通过。
可以先“暂停这个 Agent”，补充指导后再继续；其他研究员继续运行。
暂停 Agent 不取消已经提交的作业，需要在作业详情中单独“取消此作业”。

页面顶部“调整全局目标”保存一个新目标版本，暂停当前执行并取消旧作业后，
保留各路工作区，向 RSI 和所有研究员发送新目标。原本手动暂停的研究员保持暂停。
“研究约束”中可查看目标修改历史；人工指导后的实验显示“人工指导”标记。
修改请求带版本和幂等标识，过期页面不能覆盖新的目标；中途失败保持暂停，可通过恢复继续。
旧成绩和晚到的旧作业结果保留，但不参与新目标选优或达标。新验证作业绑定新的目标版本。

此入口修改自然语言目标与任务要求，不改模型、预算或已冻结的可信验收器及其数据集。
新增要求需要独立核对验证覆盖。目标修改弹窗提供“现有可信验收器仍完整覆盖修改后的目标”，
默认不勾选；未确认时禁止自动达标与最终完成判定，已有成绩仅供参考。
不能因旧验证器在新版本下运行成功就声称覆盖所有新增要求。
要更换可信验收协议或执行环境，仍需通过新的执行配置完成准备。
