# 比较计算方法

从输出依赖关系出发，区分必须计算的量、重复计算和只为接口产生的中间结果。代数改写、融合、分解和改变计算顺序，都可能改变整体成本。评估时把额外准备、临时存储和数值处理算进去，不能只看主运算的 FLOP 数。

卷积可以按空间直接计算、映射到矩阵乘，或采用适用的变换方法。隐式矩阵化避免显式展开的大中间张量，但仍有索引和数据组织成本；变换方法可能减少乘法，同时增加变换、边界处理和临时存储。核尺寸、通道数、批量及空间大小都会影响取舍。名称相同的算法也可能有截然不同的实现效率。[NVIDIA 卷积方法与性能讨论](https://docs.nvidia.com/deeplearning/performance/dl-performance-convolutional/index.html)

数学等价不保证浮点结果相同。改变归约顺序、把缩放移到另一侧、合并中间步骤或改变累加精度，都需要对照原始语义和误差标准。某个实现没有通过，只说明该实现和条件下存在差异；先定位差异来自哪里，再判断是否值得继续。不要把普通低精度路径的一次失败扩展成对全部补偿或高精度方法的否定。[PyTorch 数值精度说明](https://docs.pytorch.org/docs/stable/notes/numerical_accuracy.html)

一个值得尝试的新方向，应能说明它减少了什么工作，以及可能新增什么成本。尽早验证最关键的假设：例如额外变换是否已经超过可节省的时间，或者误差是否主要集中在某一步。关键假设成立而完整实现较慢时，可以继续改善实现；假设本身被否定后，换方向比继续调参数更有价值。

同伴的快速实现能提供局部证据，不必成为你的唯一出发点。可以借用其精度处理、索引修复或局部算子，继续验证原来的计算组织。资料中的方法需结合 GPU、编译器和任务要求重新判断，不能直接当成当前题目的答案。
