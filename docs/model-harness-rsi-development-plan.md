# 模型与 Harness RSI：研发计划草案

> 历史计划：从旧分支 `codex/model-harness-rsi` 恢复，保留原里程碑和验收思路供追溯。文中有关 Ray、旧 Runtime 和目录的描述已过时。当前阶段计划见 [roadmap.md](roadmap.md)，已实现/未验收边界见 [implementation-status.md](implementation-status.md)。

状态：2026-09-28 研发中。设计契约、实验隔离和验收规则见[最小闭环设计](model-harness-rsi-design.md)。当前代码已有 ToRL 数据冻结、TIR Harness 源码锁、单研究员候选提出、CPU 模型资产/DataLoader 预检、两种子奖励变化预检、AReaL 2.0 GRPO 与评测 recipe、确定性选版和发布/回滚的 CPU 测试。研究员 Runtime 已用公开题和合成失败反馈实跑并冻结候选，这只证明接线；真实模型轨迹驱动的优化、GPU 训练、封存集能力提升和审查轨迹 SFT 尚未验收。[当前 TIR 示例](../examples/areal_rsi_tir/README.md)列出新分支的运行准备。

## 1. 交付目标和顺序

首个可交付物是一条可以从冻结配置启动、失败后恢复并给出可信结论的 TIR/ToRL 闭环：

```text
M0,H0,TaskSet → Harness 搜索得 H1 → 固定 H1 进行 AReaL GRPO 得 M1
              → 四组交叉评测 → 封存发布或拒绝 → 下一代起点
```

首版默认一个研究员。选择 GRPO 作为第一条训练路径，是因为 TIR 已有在线采样与可计算奖励，能够更快验证 Harness→训练→发布链路；这不等于 GRPO 已证明比 SFT 更会泛化。Harness-Zero 式审查轨迹 SFT 保留为后续对照，不与首版同时建设复杂的多 Agent UI 或数据合成系统。没有提升时也交付完整的失败证据和未晋升决定。

## 2. 开工前冻结的决策

| 决策 | 当前建议 | 需预检的事实 |
| --- | --- | --- |
| 任务与数据 | ToRL 数学题，TIR 计算器工具 Agent | 数据文件、许可证、题目/答案格式、重复题和官方测试集身份；Python 后端需独立沙箱才开放 |
| 目标模型 `M0` | `Qwen/Qwen2.5-Math-1.5B` | 检查点/tokenizer 可访问、真实推理、实际 GPU 显存 |
| `H0` | TIR 非聊天模式真正生效的计算器专用提示词、解析和两轮预算 | `SYSTEM_PROMPT` 不生效的路径必须由 trace 验证；工具使用率和错误率；拒绝无沙箱 Python 工具 |
| Harness 研究范围 | 首轮仅通用提示和工具使用策略 | 候选能在同一执行器下被搜索、训练和评测加载 |
| 首次训练 | AReaL GRPO，固定 `H1` 对 `model_train` 在线采样 | 奖励可靠、同题存在混合成功/失败采样、检查点可加载、训练硬件满足配方 |
| 后续对照 | 审查轨迹 SFT 与等预算 `H0` 引导训练 | 审查轨迹无泄漏、renderer/loss mask 正确、对照预算匹配 |

若预检发现 ToRL 的有效训练/封存划分、工具执行安全性或固定模型推理不可用，先解决这些事实再冻结实验；不能用模拟推理或模型列表查询替代真实预检。

## 3. 里程碑

人日估计仅用于排期，假设一名熟悉代码的工程师、可用 GPU 节点和已有 AReaL 环境；不包含模型下载排队、集群故障、研究员/审查模型费用及正式训练运行时间。每阶段在前一阶段证据满足后开始。

| 阶段 | 预计工程量 | 主要实现 | 可审阅交付与退出门槛 |
| --- | ---: | --- | --- |
| **P0 契约和实验冻结** | 2–3 人日 | 定义 v2 数据根、具名 API、五组题集、manifest、预算和发布门槛；保留旧 run 只读 | 配置可校验；跨 split 重复、缺失摘要、答案暴露和旧记录误加载均失败；记录模型/工具/验证器身份 |
| **P1 单一 TIR 执行路径** | 3–5 人日 | 将实际生效的提示词与 TIR 执行器版本化，打包供 AReaL worker 和独立评测共同调用 | `M0+H0` 在真实任务上完成基线；train/eval 的 prompt、工具 schema、结果格式和 token budget 摘要一致；A/A 波动可测 |
| **P2 Harness 搜索与冻结** | 3–5 人日 | 单研究员提出补丁；候选 CAS、泄漏检查、开发集执行、独立选版集和成本规则 | 有 `H0`、至少一个有效候选、所有候选的真实轨迹/分数/成本及一份确定性 `H1` 选择回执；失败候选不会污染执行器 |
| **P3 AReaL GRPO** | 5–8 人日 | 固定 `H1` 的在线采样、reward/token 对齐、作业意图与回执、单一完整检查点 | 数据和奖励可追溯到题目与 Harness；先完成至少一个真实 step 的烟测，再完成预算预登记的训练并重新加载 `M1`；中断恢复不会重复提交训练作业 |
| **P4 交叉评测与发布** | 3–5 人日 | 配对四组比较、model_dev 选 checkpoint、封存集门槛、原子发布与回滚、下一代起点 | 真实四组报告及逐题证据；封存集未参与搜索/训练；成功或无增益决定可重放；回滚后旧版本仍可执行；下一代读取正确父版本 |
| **P5 审查轨迹 SFT 对照** | 5–8 人日 | Harness-Zero 式 PASS/REPLACE、成功轨迹过滤、私有信息审计、token/loss mask 构建、AReaL SFT | 真实 SFT 检查点和 rollout；审查者替换动作与原策略采样分开记录；与 GRPO 在同题同预算下走 P4 门槛 |

首版 P0–P4 粗估 **16–26 人日**，以 P1 的真实预检结果再收敛。P5 单独计入。若 P3 奖励全为 0/1 或 GPU 不满足配方，可先交付 P0–P2 和“不足以训练”的完整记录，不能把 P3/P4 伪装为已完成端到端训练。

## 4. 建议的实现切片

### 切片 A：最小可信基线

从一个配置和一个模型检查点开始，按题目 ID 输出 `EpisodeRef → VerificationResult → EvaluationReport`。优先检验解析错误、工具超时、模型失败、验证器异常四种不同结果，及同一输入重复执行时的幂等身份。真实基线和 A/A 复测通过后，才允许 Harness 候选进入搜索。

### 切片 B：Harness 候选搜索

研究员只编辑获准的 Harness 快照，不能编辑数据、验证器、工具实现或训练配置。补丁落在隔离工作区，通过静态规则与题目特异信息检查后冻结。`harness_evolve` 可提供逐题反馈；`harness_select` 在候选集冻结后只供固定选择器使用一次，不向同代研究员回传以继续搜索。借鉴 RRSI 的噪声与成本判断，但首版不引入它的全部多角色/多域控制代码。

### 切片 C：训练数据与模型作业

固定 `H1` 后，AReaL 用 `model_train` 在线生成轨迹。奖励由私有答案计算；工具返回不计为模型生成 token，独立评测从生成 token 重新验证并在验证器异常时失败。首版实际调用 AReaL `PPOTrainer` 的 GRPO 配方，只接受一次预登记训练产生的一个完整 HuggingFace 检查点，保存训练源、Harness、验证器和父模型摘要。训练失败或检查点不可加载时不得进入评测。P5 再引入审查者私有指导和 SFT loss mask。

### 切片 D：可信比较与递归

`model_dev` 只用于检查点选择和预设规则决策。正式封存评测开始前锁定候选和门槛；评测器从不可写的模型、Harness 和验证器快照启动。发布指针由代码原子更新，并留下前后版本及回滚记录。新建下一代时读取发布记录而不是研究员报告。

## 5. 目录与代码边界

遵循仓库现有 `AGENTS.md`：

- `api/records.py`、`api/research.py`、`api/execution.py` 放具名契约；只有存在真实第二实现时才在 `api/interfaces.py` 增加协议；`api/control.py` 统一 JSON 边界校验。
- `infra/research.py` 的 `ResearchSystem` 组装新闭环并提供具名 `run_id` 控制；调度与记录在 `infra/coordination/`，评测与选版在 `coordination/evaluation`、`coordination/policies`。
- TIR 任务执行与验证在 `infra/tasks/`；AReaL 连接器在 `infra/` 的具体模块中。GPU worker 通过固定 wheel/source-lock 加载同一执行器；不把 AReaL 私有配置塞入公共数据契约。
- `ui/` 在 P4 后按真实需求接入。首版使用 CLI 和只读运行报告；不复制一套前端状态机。
- 旧数据目录和历史源码锁保持只读。新 schema 不回写旧候选摘要或评测记录。

## 6. 验收用例与记录

| 验收用例 | 必须保存的证据 |
| --- | --- |
| 干净启动 | 版本锁、任务划分、模型/工具/验证器 digest、预检的真实模型调用 |
| 训练前基线 | `M0H0` 逐题结果、完整有效/无效计数、Token/工具/时间成本、A/A 波动 |
| Harness 搜索 | 候选补丁、静态检查、研究员可见轨迹、`H1` 选版原因与成本 |
| GRPO 训练 | 冻结训练题集、Harness/验证器摘要、模型生成 token 与工具观察区分、AReaL 日志和可加载 checkpoint |
| 四组评测 | 同题、同 budget、同 seed 的 `M0H0/M0H1/M1H0/M1H1` 逐题证据及汇总 |
| 发布与回滚 | 预登记门槛、封存测试访问记录、发布指针前后值、失败/拒绝/回滚回执 |
| 下一轮起点 | 第二代 manifest 的父模型/Harness 与第一代晋升记录一致 |

对基础设施边界做故障测试：作业提交后服务崩溃、训练中断、结果落盘后回执丢失、验证器超时、Harness 快照变更、旧任务重复触发。只验证实际行为和故障，不测试纯字段转发。跨模块实现运行 `make check` 并逐项报告环境跳过；真实 GPU/模型/封存集结果单独保存，不能由模拟测试代替。

## 7. 风险与阶段门槛

1. **执行不一致与工具隔离**：当前 TIR 非聊天模式使用 `TORL_PROMPT`，而文档还提及 `SYSTEM_PROMPT`；本地 PythonExecutor 无沙箱。P1 必须从实际模型请求证明哪份提示词被执行，固定计算器工具，并阻断训练和评测对同一 `H` 的哈希差异。Python 后端单独经过沙箱验收后再引入。
2. **没有有效 RL 信号**：先统计同题多次采样的奖励方差；全零或全一时重新选择预先允许的难度区间或调整采样预算，并开启新实验身份，不能修改冻结测试题。
3. **研究员信息泄漏**：研究员只读 `harness_evolve` 公开题面和反馈；禁用隐藏答案、私有 verifier 输出、封存题和宿主工作区。P5 审查者也必须遵守同一边界。
4. **小样本误判**：配对任务、重复基线、记录区间估计和成本；封存提升不确定时不宣称增益。研究员不能据此反复调整同一 sealed split。
5. **GPU 和模型服务不满足配方**：资产预检会验证本地模型/tokenizer 和控制器能构造推理参数；SGLang 版本由实际启动服务的 GPU worker 检查。最终仍须触发真实目标调用与至少一个训练 step；只有路径存在、模型列表可读或 `make check` 通过都不足以通过 P3。
6. **控制器与 GPU 部署位置**：内置研究员已在 macOS 文件沙箱下拒绝私有题集读取，并只通过本地受限隧道访问模型服务；Linux 默认无隔离 Runtime 会在 GPU 阶段前被拒绝。Mac 控制端的 Ray worker 需要相同的模型/题集绝对路径、共享实验与 name-resolve 目录，以及匹配的 AReaL、RSI 安装；如 worker 安装路径不同，应显式配置其 `PYTHONPATH`，不能继承 Mac 路径。若控制器必须运行在 Linux GPU 主机，需先实现并实测 Linux 研究员隔离；两种部署仍须在目标 GPU 集群验证。

## 8. 后续范围

P5 SFT 对照完成后再考虑数据合成：新题目先经去重、可执行验证器、难度和分布审计，作为新的 `TaskSetVersion`，并记录由哪个 `(M,H)` 产生。多 Agent、自适应并发、更多任务域和 Web 工作台应由真实运行证据驱动；它们不是最小 RSI 闭环的前置条件。
