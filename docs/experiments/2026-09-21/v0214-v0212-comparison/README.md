# v0.2.1.4 与 v0.2.1.2 Luna：并发和探索路径的区别

2026-09-21。按用户要求，v0.2.1.4-luna 七题已于北京时间 18:09:07–08 停止。
已逐题确认 status=stopped、worker_alive=false、无运行中 agent 和作业。未修改候选或给实验补发建议。

## 判断

吞吐变慢更像七题并发/API 服务条件带来的共同影响；三道题的明显分差则有更直接的探索路径和决策证据。
不能用这一轮给两种因素分配精确的因果百分比，也不能把旧版本本来就存在的问题全部归为新 prompt 引入。

同样七题并发的 v0.2.1.3，researcher 前 16 分钟平均输出 22,452 token；v0.2.1.4 为 22,963；主要三题并发的 v0.2.1.2 为 30,499。
两个七题批次在不同时间运行、prompt 也不同，因此这是相关证据，不是受控的 API 并发测量。
但它不支持“本轮新增 AGENTS/知识/skill 又造成了大幅额外吞吐退化”。

## 三个具体路径差异

### L2P71：错误地把未验证选项排除在外

两版 RULES.md 完全一致。

旧版布局研究员第 5.8 分钟区分了普通 TF32 的失败与 tf32x3 的独立通过。leader 第 7.1–7.2 分钟核对源码和正式反馈，将这一经验分享给另外两人。
此后不仅调参数，还结合输出布局、常量特化、K 分块；GPU 执行研究员第 13.5 分钟达到 0.497 ms，约 3.119x。

本轮 GPU 执行研究员第 2 分钟把“必须显式 ieee 才符合规则”写进开局报告。
leader 第 2.5 分钟回复“你的 strict-ieee 判断是当前最需要固定的语义前提”。
第 8.7 分钟又从普通 TF32 的失败推断“strict-fp32 必须 IEEE，任何 Tensor Core shortcut 只能作上界诊断”。
随后团队主要围绕 0.708–0.717 ms 的 K-major IEEE 方案复现与微调，直到停止最好仍约 2.189x。

本轮资料本来就说明 ieee/tf32/tf32x3 需要分别验证，因此不是资料明文禁止了该路径。
这是 researcher 的过度推断被 leader 强化；并发会减少纠错机会，但不会直接证明这个推断成立。

### L1P77：相同稀疏性发现，落在不同的计算组织

两轮都发现只有奇数子格需要计算，都共享并逐渐采用领先代码，因此“发生趋同”本身不足以解释差异。
旧版采用 `[27,Cin,Cout]` 权重组织及对应 GEMM，第 12.4 分钟记录 0.836 ms；后来修复 bias 分支的有效候选约 0.839 ms。
本轮采用 `[Cin,Kd,Kh,Kw,Cout]` 的另一种归约/地址组织，早期停在约 1.35 ms，随后多人重复测试 warp、stage、K tile。
不能把差异简化为照搬旧版一个 M=64 参数：本轮自己的 M=64 实验实际更慢，底层代码组织不同。
leader 需要协调检验不同布局和归约组织，而不只是同步当前版本的最佳参数。

### L1P63：新 profile 没有及时形成更强的结构假设

两版 RULES.md 也完全一致。
旧版算法研究员第 8.1 分钟已验证 tf32x3 的 15.6 ms 候选，此后 K 分块及地址组织继续改善至约 12.5 ms。
本轮早期多人仍在 30–80 ms 的 implicit GEMM 上调整执行配置。
GPU 执行研究员确实 profile 到单个卷积 kernel 占主要时间，但这一观察本身没有解释为何慢；后来在自己的 K16/显式 stride 组织上 tf32x3 也未优于 IEEE。
这说明不能只把精度模式或一个参数当作独立的万能经验，必须与计算/布局组织一起形成可验证假设。

## 对新增模块的评价

- 更频繁看轨迹不等于判断更准确。旧版前 16 分钟几乎不调用 read_researcher_trace，本轮每题都调用；leader 上下文明显变大，L2P71 的不充分结论仍未纠正。
- 并不是本轮指导条数普遍更多。L2P71 前 16 分钟旧版约 24 条、新版约 15 条；L1P77 约 25 条对 19 条。主要问题是指导内容和保留哪些未验证可能性。
- 旧版也有大量追随、重复复测、过早“最终完成”。它在几题上更早找到了较好的结构，不能据此认为旧 leader 已经稳定掌握更好的搜索策略。
- L3P19、L3P28 本轮前 25 分钟更好，说明不能把知识和 profiling 一概判为有害；目前更准确的评价是收益不稳定，新增观察尚未解决原来的决策弱点。

若继续验证，优先保持相同版本只将并发恢复为三题，在 L1P63/L1P77/L2P71 上复测；不要同时修改 prompt、资料和协作机制。
策略改进应聚焦：区分任务明确要求、单次实验失败、仍待验证的推断；当多人都已复现同一平台期时，保留研究不同计算组织的空间。
这些建议未在本次中止的运行里实施。
