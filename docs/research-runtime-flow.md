# 当前研究流程与卡点

研究方法、分工策略和报告写法由 Agent 决定；系统负责保存状态、投递消息、执行工具和恢复工作。

## 一次研究怎样推进

| 步骤 | 谁负责 | 系统做什么 | 下一步怎样发生 |
| --- | --- | --- | --- |
| 明确需求 | 用户与 Interaction | 保存自然语言需求、资源限制和验证约定 | Interaction 将需求交给 RSI |
| 组织研究 | RSI | 保存计划，创建研究员和任务节点 | 任务作为消息送入持久会话 |
| 调研与实现 | Research Agent，也可以是 RSI | 执行模型请求、文件和 shell 工具，归档资料 | 工具结果回到同一会话 |
| 执行实验（可选） | 当前 Agent | 固定作业输入，保存参数、候选和节点归属 | 作业结束后唤醒订阅者 |
| 总结本轮 | Research Agent | 保存报告并关联任务、节点、证据；停止推理 | 报告投递给 RSI |
| 决定下一轮 | RSI | 新派单关联上一份报告，继续原会话 | 继续、调整、共享、停止或明确等待 |
| 收尾 | RSI | 核验选中候选和正式结果，保留最终状态 | 达标结束，或如实记录停止原因 |

任务节点不是一次 GPU 提交。一个节点可以包含调研、排错、多次工具调用或实验，也可以只得到一个发现，没有候选和验证。

有两种等待：

- **等作业：** 当前任务未完成；结果回来后继续同一节点。
- **等 RSI：** 本轮已报告；研究员停止推理，只有 RSI 的下一项任务才会继续。

RSI 可以在其他方向工作时继续调研；没有可执行工作时等待事件。等待不会周期性调用模型。

## 本轮基础修复

任务、节点、报告、证据、候选、作业和会话已经由系统维护。这次没有重做这些数据模型。

1. **报告后的调度兜底。** 从现有节点和等待状态生成待回复列表。RSI 普通回复后进入空闲、却漏掉已送达报告时，调度器追加一次持久提醒。明确等待、等待用户或作业、暂停和停止时不催办。每份报告最多提醒一次，重启和轮询不重复唤醒；研究员不会自行开始下一轮。若模型仍不处理，待回复状态保留，不靠无限自动调用掩盖问题。
2. **事件存储。** 使用进程间锁和可恢复序号索引，避免不同写入者争抢序号，以及每次追加、增量读取都扫描完整历史。旧档案可以初始化索引；事件先落盘、索引后更新，中断后从已落盘尾部恢复，历史事件不重写。
3. **HTTP 客户端生命周期。** 连续回合和重叠 Agent 共享客户端连接池，凭证和超时仍逐请求设置。取消一个 Agent 只关闭它的响应，最后一个调用者退出后关闭客户端。服务端允许且响应完整消费时可复用底层连接；SSE 收到终态后仍及时返回，不无限等待流关闭。持续重试规则不变，第三方服务错误仍可能发生。

## 本轮流程简化

RSI 自主决定分工和人数。派单应说明一个需要解决的问题，让研究员在范围内完成实现、排错和多次实验；不默认要求每次提交后都申请下一步。正式报告仍停止推理并等待 RSI，普通执行进度不需要额外汇报。

执行使用 `run_job(wait=true)`：短作业直接返回，长作业由系统等待，完成反馈直接进入原会话。选中输入的独立复测使用 `rerun_job`，收集产物可以直接保存为候选；这些操作仍使用原有作业、候选和预算模型。无需为了复制文件、核对哈希或整理已有结果另开研究节点。

compact 改为优先参考实际 token 用量，保留近期原始对话与工具反馈，只总结较早内容。不会因为加密 reasoning 字符串很长就提前压缩。摘要、恢复规则和三个角色的 prompt 均用简洁中文，持续授权与现有约束由系统记录恢复。

## 仍需观察的卡点

| 环节 | 现象 | 要讨论的具体问题 |
| --- | --- | --- |
| 模型请求 | 慢响应、断流、重试 | 区分正常调用与服务故障；连接池不能保证服务端稳定 |
| 当前任务内 | 长时间读资料、核对，没有新发现 | 是必要定位还是重复工作，需要看实际轨迹 |
| 多题分工 | 一个方向顺序处理多题 | 任务粒度、独立上下文和并行安排 |
| 汇报与协调 | 等待不烧 Token，但可能阻塞研究 | 等待是否有真实依赖；提醒不替代研究决策 |
| 候选收集与复测 | 反复找文件、算摘要、整理已有结果 | 哪些操作应直接交给确定性工具 |
| 上下文恢复 | compact 后重读旧材料 | 保留哪些事实，如何减少重复恢复 |

这些问题不能全部称作基础 bug，也不能只凭“没有加分”判断探索无用。以上改动减少机械往返；真实研究所需的推理、排错和评测时间仍取决于任务与服务表现，需要通过下一次实验衡量。
