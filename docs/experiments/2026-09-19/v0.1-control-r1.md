## L3P10：不是不同算法取胜，而是保留了一条不同的实现探索

四人都在首次 leader 干预可能发生前独立选择了相近的 NHWC / tf32x3 / 融合 BatchNorm 路线。这种初始趋同在纯隔离下仍然存在。首版全部因约 3–4e-4 的误差失败，随后也都集中处理训练态 BatchNorm 与卷积求和顺序。

R3 的关键时间线如下，均为约数；具体事件与有效时间见 data.json 和 R3 文本轨迹。

- 前 15 分钟：确认训练态误差放大，逐层比较并保留精确卷积路径。
- 约 21 分钟：一度认为双遍归约比 Welford 更接近参考。
- 约 31 分钟：构造输入与线程结构诊断促使它重新考虑在线均值/方差，而不是永久排除先前表现不好的 Welford。
- 约 45 分钟：联合处理线程内在线统计、跨线程加权求和，以及方差缩放和 epsilon 的 FMA 舍入；局部匹配后立即做整网正式检查。
- **45.78 分钟**：0.4689×，首个正式正确版本；**47.10 分钟**：0.5397×。
- 最后十余分钟：逐步把不敏感的后段卷积改为更快路径，最终探索达到 1.0477×，独立复测 1.0989×。

其他三人也有真实的局部进展，但没有完整通过。这仍是典型的后半程只有一条线突破的情形。它说明两个问题：没有好分数的长期探索可能非常有价值；同一算法名称下，不同的舍入、归约假设也构成有用的探索差异，不能只用“都在做 BatchNorm”判断重复和决定 reset。

v0.2.4 的 R3 先尝试过 leader 提出的 FP64 局部累加假设，随后接入 R4 的局部 Welford 版本（mean 58/64、invstd 64/64），整网仍失败。最后的全匹配局部修正来得很晚。其中发给 R1、R3 的两条建议分别晚于个人预算结束 42.8 秒和 17.6 秒，均未确认读取。

这与“未完整验证的局部经验成为共同实现基础，独立的细节探索减少”相符，但尚不能证明某条建议必然阻止了本可发生的突破。两轮都有大量局部诊断；纯 pass@4 的诊断次数甚至更多，不能简单归因为协作版做了太多诊断。更应关注哪些假设被保留、推翻或重新尝试，以及局部结果何时进入完整验证。

## L2P71：更多独立方向不自动意味着更好成绩

Astra 的四人独立探索后仍得到相近的高分，其中三人约 4.6×。他们也自行调查数值范围，说明 v0.2.4 的这类有效性工作不全是 leader 强加的。本批撤回远少于 v0.2.4 的 111 次，但不能据此推断所有未撤回实现都有相同的广域 FP32 保证。正式随机检查与全面语义证明不是一回事。

Sol 的方向更分散，却明显弱于协作版：R3 花了不少时间尝试 CUDA、Winograd，再转向 Tensor Core 和参数调整；R1 从直接 FMA、IEEE GEMM 逐步进入 tf32x3；R4 后期才发现权重预打包的收益。v0.2.4 中，相似的可用代码和经验被更早复用、组合，四人最终都接近 4.9×。这提供了共享有实际价值的正面案例。

本批 Sol R2 在约 22 分钟把 0.577 ms 描述为接近输出带宽下界，后续仍继续尝试，但没有超过这个成绩。协作版更快的有效测量说明这个上限判断至少过早。未来 leader 可以用本 run 的可靠反例帮助接收者重新审视瓶颈，而不必直接要求复制完整代码。

还发现一个具体的正确性维护行为：Sol R2 在末段确认某批 `empty_strided` 候选写入了底层存储之外的 padding，主动撤回 12 个候选，并保留完整分配后返回视图的安全版本。最初 12 次撤回引用了不存在的 report ID，被工具拒绝；随后使用真实报告引用完成撤回。三个 checkout 拒绝也是未保存修改的正常保护。这些不是候选选优丢失或 Runtime 失败，最终选优已排除被撤回的候选。

## 下一步

继续 v0.2.5，仍以 v0.2.4 为未晋级的工作 base，单独测试登记经验最多增加一名接收者，并明确移除状态查询中的隐含报告广播；保留按需读取同 run 资料。本对照的晚期正确性突破提示：要检查限额是否保留不同实现假设，同时观察它是否损失 Sol 这类有用的早期复用。

批次间补一个小的发送反馈修复：拒绝给已经停止的研究员发新建议，避免返回无法交付的 queued。它不改变原有预算或已在预算内发出的建议；原 v0.2.4 数据保留，不把两次晚发当作整轮工程失效。更广泛的会话退休修复仅在重启版本启用前接入。

v0.2.6 继续关注建议粒度、旧建议的纠正和完整验证；v0.2.7 判断停滞时必须结合局部证据，不能以短期没有分数为唯一依据。目前没有版本晋级，也不提前叠加尚未验证的改动。

证据入口：`analysis/summary.json`、`analysis/*-data.json`、逐 agent 轨迹文本、`analysis/*-sharing.json`、`analysis/researcher-curves.png`。历史 v0.1 的旧模型/墙钟预算数据单列在 campaign 的 `historical-results.json`，不混作本轮严格对照。
