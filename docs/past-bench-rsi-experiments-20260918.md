# AReaL-RSI 单 Agent 与多 Agent：PAST-Bench Harness 优化总结

整理日期：2026-09-18。两组均已完成；本文依据正式评测记录、逐轮账本和完成后的运行状态整理，不包含 Codex Goal 组。

利用 AReaL-RSI 优化模型 `gpt-6-astra` + Hermes Task Agent 在 PAST-Bench 上的表现。优化对象限定为 Harness，包括提示词、执行流程、工具、记忆、上下文管理和 skills 源码；不修改模型权重、任务、grader 或评测适配器。

目标：分别完成单 Research Agent 的 30 轮优化，以及 3 个 Research Agent 各 10 轮优化，对比两种研究组织方式的结果与资源消耗。

本实验不是完整 PAST-Bench 全量评测。锁定划分为 develop：SM01、search：SM02、final：SM05；两组没有额外执行 develop/diagnostic。每次正式评测在对应 family 内运行完整的持久化开启/关闭对照。

## 结果

本次选择指标是 `evaluation_lift = evaluation_score − without_persistence_score`，即同一 Harness 开启和关闭持久化的分数差。它不是相对初始 Harness 的优化提升；优化提升需要在同一 search 划分上将候选与 seed 比较。

## 实验设置与版本选择

研究模型和 Task Agent 模型固定为 `gpt-6-astra`，研究推理强度为 `xhigh`；judge 沿用共同 lock。两组从相同的 Hermes 初始源码开始，各自独立评测 seed、保存候选和记录；两组之间不共享优化候选或经验。

每个有效优化轮必须包含实质 Harness 改动、独立源码版本和一次成功的完整 search 评测。本地合成测试、准备阶段、失败尝试及重复测量不计入 30 轮。

选择顺序为 search 的持久化收益优先，其次开启组绝对分，再次改动更少；seed 也参与选择。完成规定轮数后冻结唯一最佳候选，只做一次 final，不根据 final 继续选版或优化。

本次 RSI Agent 依据正式分数与规则进行决策、协调和最终冻结，框架负责保存候选、执行评测和记录结果。不能直接套用之前 TB2.1 实验中“固定 workflow 自动选择 validate 最高分”的过程描述。

所有候选独立保存，加载时选择不可变 candidate_id；当前工作区不一定是最终最佳版本。单 Agent 组结束时工作区仍是 R30，交付版本是 R18。

### 最佳版本 R18 的具体改动

原实现存在无效 JSON 参数前期重试缺少有效反馈、非对象 JSON 可能被静默转成空对象的问题。R18 调整共同执行入口：先校验整个工具调用批次，全部合法才规范化参数并继续执行；首次发现错误就给出逐调用匹配的 Error/Skipped 回执，保留错误批的原始参数，并且整批不执行。

这一改动旨在减少没有信息增量的重试，以及错误参数被默认值掩盖的情况。局部合成检查支持其代码行为，但仅凭一次聚合分数上涨，不能证明具体子机制贡献了多少收益，也不能证明收益稳定。

R19、R30 等组合未保留 R18 的额外 0.008 收益，因此没有默认将它们合入最终版本。

## 多 Agent 优化过程

RSI 实际创建三个研究员，各有独立工作区和候选分支：A 研究执行流程与工具，B 研究记忆写入、检索和更新，C 研究上下文、迁移与 skills。

三个研究方向可以并行准备，但正式评测受单作业限制串行进行。候选基本按 A1 → B1 → C1 → A2 → B2 → C2 的顺序完成。三人共享本组一次 seed baseline，最后由 RSI 选择全局最佳并执行一次 final，不是每人各跑一次 final。

| 本地轮次 | A：执行与工具 | B：记忆与检索 | C：上下文与迁移 | 三者 search lift |
|---|---|---|---|---:|
| 1 | 检索依赖屏障与执行闭环 | 当前记忆 read 与作用域纠错 | 技能适用范围、前提及证据元数据 | 均 0.584 |
| 2 | 去掉硬屏障，仅保留执行提示 | 摘要附用户原话 | 压缩保留原始证据、纠正及核验状态 | 均 0.584 |
| 3 | 工具结果状态与失败恢复注记 | 装载实际命中的 child 会话分片 | 按当前请求自动加载少量匹配技能 | 均 0.584 |
| 4 | 前台学习检查点 | root 会话有界原文窗口 | 用户 turn 边界刷新记忆与技能片段 | 均 0.584 |
| 5 | 基于调用身份去重 | 有界检索续页，最多 500 hits | 任务邻近位置加入同快照记忆提醒 | 均 0.584 |
| 6 | A1 屏障 + A3 结果注记 | B5 续页 + B3 分片装载 | C4 刷新 + C5 位置提醒 | 均 0.584 |
| 7 | 逐项后置条件与完成证据提示 | B3 分片 + B4 原文窗口 | 压缩保留有界调用方原文锚点 | 均 0.584 |
| 8 | 无效 JSON 首次立即逐调用反馈 | 原子多条记忆 merge | 按需检索 skills 正文 | 均 0.584 |
| 9 | 面向当前决策缺口形成检索查询 | 按消息时间 recent 排序 | 分离稳定程序与案例输入，按当前请求绑定 | 均 0.584 |
| 10 | A9 查询提示 + B7 分片原文窗口 | B9 recent + B7 原文窗口 | C8 技能发现 + C9 输入绑定 | 均 0.584 |

全部 30 个候选的实际快照父版本都是共同 seed；组合候选另外记录移植来源。因此本组不是三条各自累积十次修改的演化链。

本次已经尝试多种组合，包括跨研究员的 A10（A9 + B7）。所以可改进点不是“完全没有融合策略”，而是如何根据证据决定哪些机制值得组合，以及怎样检验组合的互补或干扰。本次组合均未测得 search 收益。

## 结论

单 Agent 完成 30 轮后，找到一个在 search 上提高 0.008 的源码修改；多 Agent 完成同样总轮数，没有找到超过 seed 的版本，并消耗了约 1.68 倍优化侧 tokens。在本次固定组织方式与任务子集下，没有观察到多 Agent 优于单 Agent。

两组 final 开启组均为 1.000，但其中多 Agent 组使用的就是 seed。不能用 final 满分声称优化有效，也不能据一次实验认定单 Agent 普遍更好。

Search seed 开启组已经是 0.984，距离满分只有 0.016；单 Agent 唯一正向候选也只提高 0.008，其余 59 个候选均与各自 seed 同分。这说明当前测量的可区分空间很小，但不能仅凭同分断定代码未加载、机制未触发或机制无效。

## 可改进点

1. **提高搜索信号的区分度。** 下一次实验预先选择更有提升空间、覆盖更多能力的 search family，并保留独立 final；不要在当前实验结束后改划分来重解释结果。
2. **复验小幅收益。** 为 seed 和入围候选预留同划分独立重复评测，确认 0.008 的改善是否稳定；final 上也应预先安排 seed 对照，避免缺失同划分基准。
3. **增加不泄题的机制观测。** 汇总工具参数拒绝、记忆读写、检索命中、技能加载、压缩等触发次数，以区分机制未触发、触发但未采纳、采纳但未得分等情况。
4. **控制多 Agent 协调与审计成本。** 用结构化轮账自动检查候选唯一性、次数、预算与串行依赖，减少模型反复转录和确认；具体节省空间需先做调用归因。
5. **使调度能力匹配协作要求。** 本次 C10 曾因缺少通用消息等待工具及真实前驱 job 信息而上报阻塞。应明确提供等待/交接接口，避免“要求等待却没有可执行等待动作”。
6. **按证据分配搜索预算和组合候选。** 可在预先约定规则下使用分阶段筛选、分支预算调整或搜索算法；保留独立复验，防止挑选偶然高分。已有组合实验不能直接等同于系统化融合搜索。
7. **补齐成本口径。** 分开记录研究、协调、Task Agent、judge 的输入/输出/cache tokens、请求数、费用、运行及锁等待时间，再进行完整成本效率对比。
